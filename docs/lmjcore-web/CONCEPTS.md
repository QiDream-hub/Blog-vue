# LMJCore-Web 概念与存储模型

本文解释 LMJCore-Web 的核心概念与底层存储模型，是阅读 API 文档前的背景材料。端点契约见 [API_REFERENCE.md](./API_REFERENCE.md)，链式查询设计见 [QUERY_DESIGN.md](./QUERY_DESIGN.md)，批量事务设计见 [BATCH_DESIGN.md](./BATCH_DESIGN.md)。

## 1. 指针（Pointer）

LMJCore 使用 **17 字节全局唯一指针** 标识所有实体：

- **格式**: 34 位十六进制字符串
- **类型前缀**:
  - `01` = 对象 (LMJCORE_OBJ)
  - `02` = 集合 (LMJCORE_SET)
- **示例**: `01abc123def456789012345678901234`

指针同时承担「实体 ID」和「实体类型」两个职责：前两个十六进制字符即类型前缀。存储层只把它当作不透明载荷，API 层则依赖前缀区分对象与集合。

**实体空间预先存在，指针是该空间中的定位符**：`POST /obj`、`POST /set` 只分配指针、不写任何存储，因此返回的指针一开始处于**空态**；首次写入成员/元素时指针才被**实化**。空态是合法的默认状态，指针本身不会因为“还没有内容”而失效。

### 1.1 术语

| 术语 | 含义 |
|------|------|
| **指针** | 17 字节全局唯一标识，同时表示实体类型与位置 |
| **空态** | 指针已分配但尚无任何成员/元素；`set` 库中无对应 Key，默认状态 |
| **实化** | 首次写入成员/元素，使 `set` 库出现该指针的 Key |
| **缺失值** | 成员已在 `set` 注册，但 `main` 中暂无值（合法中间状态） |
| **幽灵成员** | `main` 中有值但 `set` 未注册（严重数据损坏） |

## 2. 对象与集合

| 维度 | 对象 | 集合 |
|------|------|------|
| **用途** | 键值对容器 | 无序元素容器 |
| **指针前缀** | `01` | `02` |
| **存储** | 成员名在 `set` 库，值在 `main` 库 | 元素在 `set` 库 |
| **访问** | 通过成员名点查 | 遍历或判断是否已实化 |
| **典型场景** | 配置、用户信息、文档 | 标签、权限组、唯一值列表 |

对象提供按成员名的 O(1) 点查；集合只提供成员资格判断与遍历，元素本身没有名字。两者可以互相嵌套：对象的成员值、集合的元素值都可以是另一个对象或集合的指针。

## 3. 两套类型表示：存储标签 vs API 类型

代码中同时存在两套「类型」表示，分别服务于**存储编码**与**对外 API**，属于不同层次，不能互相替代：

| 层次 | 表示 | 取值 | 出现位置 |
|------|------|------|----------|
| 存储编码 | `LMJCORE_VALUE_TYPE_*` 宏 | `RAW=0x00`、`PTR=0x01`、`NULL=0x02` | 每个值落库时的**首字节** |
| API 呈现 | `api_value_type_t` 枚举 | `raw`、`null`、`object`、`set` | 响应 JSON 的 `type` 字段 |

不能合并成一套的原因：

1. **存储层只区分「是不是指针」**：对象引用和集合引用落库时都是 `PTR(0x01)`，真正的 obj/set 由 17 字节指针载荷的首字节（`01`/`02`）决定。存储层因此**不需要** `object` / `set`，只需要 `PTR`。
2. **API 层需要区分对象与集合**：调用方必须知道引用指向对象还是集合，因此把 `PTR` 拆成 `object`、`set` 两个对外类型；API 层**从不暴露** `PTR` 本身。
3. 两套类型是「多对一」映射：

   | 存储标签 | API 类型 |
   |----------|----------|
   | `RAW` | `raw` |
   | `NULL` | `null` |
   | `PTR`（载荷首字节 `01`） | `object` |
   | `PTR`（载荷首字节 `02`） | `set` |

4. **写入用字符串，读回用枚举**：写接口（`PUT`、集合增删）的 `type` 取 `raw` / `ref` / `null`，其中 `ref` 对应存储标签 `PTR`；读接口再按指针载荷细分为 `object` / `set`。

### 3.1 读接口与写接口的类型词汇

| 方向 | 允许的 `type` | 含义 |
|------|---------------|------|
| 写（`PUT /obj/{ptr}/{member}`、集合增删） | `raw` | 原样存储为原始数据 |
|  | `ref` | 存储为指针引用，`value` 必须是合法 34 位十六进制指针 |
|  | `null` | 存储为空值，`value` 内容被忽略 |
| 读（成员读取、完整对象/集合、链式查询） | `raw` | 原始数据 |
|  | `object` | 对象引用，`value` 为 `01…` 指针 |
|  | `set` | 集合引用，`value` 为 `02…` 指针 |
|  | `null` | 空值，`value` 为字符串 `"null"` |

> `api_value_type_t` 中 `VALUE_TYPE_RAW=0`、`VALUE_TYPE_NULL=2` 与存储标签数值相同，只是为映射方便；`VALUE_TYPE_OBJECT=4`、`VALUE_TYPE_SET=3` 是纯 API 概念，而 `PTR=1` 只存在于存储层。**两套枚举属于不同域，不要相互强转。**

## 4. 存储模型

LMJCore 使用两个 LMDB 数据库协同工作：

| 空间 | 名称 | 用途 | 关键特性 |
|------|------|------|----------|
| **集合区** | `set` | 存储实体的关联项集合（成员名或元素） | 启用 `MDB_DUPSORT`，按字典序自动排序，**不保留插入顺序** |
| **主存储区** | `main` | 存储具体值 | Key = `[17B 实体指针][成员名]`，点查 O(1) |

### 4.1 set 库（集合区）

| 属性 | 说明 |
|------|------|
| **用途** | 存储实体的关联项集合（对象的成员名列表、集合的元素列表） |
| **Key** | 实体指针（17 字节） |
| **Value** | 成员名（对象）或元素值（集合） |
| **特性** | 启用 `MDB_DUPSORT`，允许重复 Key，按 Value 字典序自动排序 |
| **空键行为** | 不允许空键：删除最后一个 value 时，Key 被 LMDB 自动删除 |

### 4.2 main 库（主存储区）

| 属性 | 说明 |
|------|------|
| **用途** | 存储对象成员的具体值 |
| **Key** | `[17B 实体指针][成员名]` |
| **Value** | 二进制原始数据或指针引用 |
| **Key 限制** | ≤ 511 字节 → 成员名最大 493 字节 |

### 4.3 值存储格式

所有值落库时统一添加 1 字节**存储标签**，对应上文「[两套类型表示](#3-两套类型表示存储标签-vs-api-类型)」中的 `LMJCORE_VALUE_TYPE_*`：

```
┌──────────────────────────────────────────────────────┐
│ 原始数据 RAW  ：  [0x00][data...]                     │
│ 指针引用 PTR  ：  [0x01][17B 指针（首字节 01/02）]    │
│ 空值     NULL ：  [0x02]                              │
└──────────────────────────────────────────────────────┘
```

对外响应不直接暴露存储标签，而是经 `api_value_type_t` 转换为 `raw` / `null` / `object` / `set`。

### 4.4 存储示例

对象 `{ "name": "Alice", "age": 30 }`：

```
set（集合区）：
┌──────────────┬───────────────┐
│ Key: ptr_obj │ Value: "age"  │ ← 成员名集合（无序）
│ Key: ptr_obj │ Value: "name" │
└──────────────┴───────────────┘

main（主存储区）：
┌─────────────────────┬───────────────┐
│ Key: ptr_obj+"name" │ Value: "Alice"│ ← 独立格子，由「指针 + 名称」定位
│ Key: ptr_obj+"age"  │ Value: 30     │
└─────────────────────┴───────────────┘
```

集合 `["banana", "apple"]`：

```
set（集合区）：
┌──────────────┬────────────────┐
│ Key: ptr_set │ Value: "apple" │ ← LMDB 按字典序排序
│ Key: ptr_set │ Value: "banana"│
└──────────────┴────────────────┘
```

## 5. 指针状态：空态与实化

指针的状态完全由 `set` 库中是否存在以该指针为 Key 的条目决定：

| 状态 | 判定条件 | `lmjcore_entity_stat` |
|------|----------|------------------------|
| **已实化** | `set` 中存在该指针的 Key，且至少有一个 value | 1 |
| **空态（默认态）** | `set` 中无对应 Key：刚分配尚未写入，或成员/元素已被全部删除 | 0 |

> ⚠️ **重要**: 由于 `set` 基于 LMDB 的重复键（`MDB_DUPSORT`）实现，**不允许空键**。当删除最后一个成员/元素时，该 Key 会被 LMDB 自动删除，但**指针本身仍然有效**——只是回到空态。空态是合法的默认状态，不是“实体不存在”。

### 5.1 删除最后一个成员/元素的后果

**对象场景**：

```js
// 初始状态：对象有一个成员
{ "name": "Alice" }

// 删除最后一个成员
DELETE /obj/01abc123.../name

// 结果：指针回到空态（仍然有效）
GET /obj/01abc123...  // → 404 Not Found，表示没有可读内容
```

**集合场景**：

```js
// 初始状态：集合有一个元素
["apple"]

// 删除最后一个元素
DELETE /set/02def456.../elements
{ "value": "apple" }

// 结果：指针回到空态（仍然有效）
GET /set/02def456...  // → 404 Not Found，表示没有可读内容
```

这意味着：

- 删除**最后一个成员/元素**后，该指针在 `set` 中不再有 Key，但指针依然有效；
- HTTP 404 只表示“当前没有可读/可操作的内容”，**不表示指针被销毁**；
- 对同一个指针再次 `PUT` 成员或 `POST` 元素即可重新实化，无需重新分配指针。

**建议**：

- 需要“保留空对象/空集合”语义时，写入占位成员（如 `_empty: null`）；
- 不要在应用层把 404 当作“指针已失效”。

### 5.2 空态上的操作

| 操作 | 行为 |
|------|------|
| `PUT /obj/{ptr}/{member}`、`POST /set/{ptr}/elements` | 成功，并完成首次实化 |
| `GET /obj/{ptr}`、`GET /set/{ptr}`、读取成员 | 404，表示无内容 |
| `DELETE` 成员/元素/实体 | 404，表示没有可删除的内容 |
| `GET /ptr/{ptr}/exist` | `exist: false` |
| `POST /obj/init {}`、`POST /set/init []` | 201，返回空态指针，计数为 0 |

## 6. 集合的无序性

LMJCore 中的集合是**无序集合**，具有以下特性：

| 特性 | 说明 |
|------|------|
| **无序性** | 不保留插入顺序，按字典序自动排序 |
| **唯一性** | 同一元素在集合中只能出现一次 |
| **高效查找** | 可快速判断元素是否存在 |
| **集合运算** | 天然支持并集、交集等操作（基于排序） |

> 💡 **如果需要有序列表**: 在元素值中编码顺序信息（如前 4 字节为小端序下标）。

## 7. 初始化值映射（init）

`POST /obj/init` 与 `POST /set/init` 使用同一套嵌套工具解释请求体中的 JSON 值，**不做类型推断**：

| JSON 值 | 存储类型 | 说明 |
|---------|----------|------|
| JSON object | `object`（引用） | 递归分配嵌套对象指针并填充，成员/元素值指向其指针 |
| JSON array | `set`（引用） | 递归分配嵌套集合指针并添加元素，成员/元素值指向其指针 |
| JSON `null` | `null` | 空值 |
| JSON string | `raw` | 原样存储为原始数据（**即使内容形似指针**；空串存为空原始数据） |
| JSON number | `raw` | 按其 JSON 数字文本存储（如 `21` → 存 `"21"`） |
| JSON boolean | `raw` | `true` → `"true"`，`false` → `"false"` |

- init 不做类型推断：所有标量一律按原始数据存储。若需建立对已有指针的引用，请用 `PUT /obj/{ptr}/{member}`（`type: "ref"`）或 `POST /set/{ptr}/elements`（`type: "ref"`）设置
- 空对象 `{}` / 空数组 `[]` 返回空态指针（201，计数为 0），之后写入成员/元素即可实化
- 嵌套深度上限 64，超出返回 400
- 嵌套创建的子实体失败时与整体一起回滚，不留任何半成品
- 集合自动去重：`POST /set/init` 中重复的元素（包括重复的 `null`）不报错
